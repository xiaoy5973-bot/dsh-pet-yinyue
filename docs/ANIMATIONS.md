# 动画清单

五套动画全部为 **VP9 + Alpha** 编码的 `.webm`，1280×720，24fps，透明背景。
人物在画面中的位置已统一（脚底基线 y=655、水平居中 x≈625），切换动画时不会跳位。

| 文件 | 帧数 | 时长 | 播放方式 | 用途 |
|---|---|---|---|---|
| `待机.webm` | 239 | 9.96 s | 循环 | 日常站立待机 |
| `回应-挥手.webm` | 79 | 3.29 s | 单次 | 点击宠物的回应动作 |
| `工作中.webm` | 92 | 3.83 s | 循环 | AI 干活时的状态动画 |
| `小动作-抖耳朵.webm` | 121 | 5.04 s | 单次 | 待机中随机插入的小动作 |
| `仪态-贵妇行礼.webm` | 145 | 6.04 s | 单次 | 待机中随机插入的小动作 |

## 配置里的对应关系

```jsonc
"animations": {
  "idle":   ["待机"],              // 待机循环
  "clicks": ["回应-挥手"],          // 点击回应
  "categories": [                  // 随机小动作，按 weight 分占比
    { "id": "银月专属", "weight": 15,
      "actions": ["小动作-抖耳朵", "仪态-贵妇行礼"] }
  ],
  "events": {
    "workStatus": [                // 六档工作状态，索引即档位
      "工作中", "工作中", "工作中",   // 0 思考 / 1 工作 / 2 整理 —— 循环
      "待机",                      // 3 等待 —— 循环
      "回应-挥手",                  // 4 成功 —— 播一遍
      "待机"                        // 5 出错 —— 播一遍
    ],
    "whisper": ["待机"],           // 碎碎念时的动作
    "balance": ["待机"]            // 余额气泡时的动作
  }
},
"animationWeights": { "idle": 85, "turn": 0, "move": 0 }
```

`turn` / `drag` / `moves` 仍是空池 —— 银月目前不会转向、不会被拖拽播放专属动画、
也不会随机走动。需要的话可以自己补素材。

`animationWeights` 里 `idle=85` + 分类 `weight=15` 合计 100，意思是每次动画播完
重抽时，85% 继续待机、15% 插一个小动作。这个比例由注册器按动作数量自适应，
见 [README「跑注册器」](../README.md#3-跑注册器)。

## 关于「工作中」的循环

源素材里有两次视线移动，直接首尾相接会看出跳帧。当前版本是把三段区间
（`34–89` + `90–108` + `16–33`）拼接，并在第二个接缝处做了 5 帧交叉溶解，
让循环接缝的帧差落在自然相邻帧的范围内。

## 想自己加动画？

两步：**做素材**（有绿幕视频才需要）→ **注册**（必做）。

### 第一步：绿幕视频 → 素材

```bash
python tools/build_asset.py 素材.mp4 --name 待机-呼吸
```

工具内部按顺序做：抠像 → 对齐到「待机」的身高/脚底/中心 → 亮度对齐 → VP9+Alpha 编码，
直接产出 `pet/yinyue-animation/待机-呼吸.webm`。

抠像用的是归一化绿度 `E = (G - max(R,B)) / G`，对光照渐变的绿布也稳；
被头发围住、且面积大又紧邻肤色的绿色区域判为眼睛保留，其余当背景缝抠掉；
边缘做 despill，白发和尾巴不会留绿边。缩放走预乘 alpha，透明边缘不渗灰。

常见参数：

| 参数 | 用途 |
|---|---|
| `--loop N` | 尾部 N 帧交叉淡化回第 2 帧，做无缝循环 |
| `--trim a,b` | 只取第 a~b 帧 |
| `--like X` | 对齐基准动画，默认「待机」 |
| `--feet/--height/--center` | 手动覆盖对齐目标 |
| `--dry-run` | 只测量不写盘 |
| `--keep` | 保留中间帧 |

依赖 `numpy`、`Pillow`、`ffmpeg`。

### 第二步：注册

把 `.webm` 放进 `pet/yinyue-animation/`，**文件名按下面的规范起**，然后跑注册器：

```bash
python tools/register_actions.py                 # 改已安装的那份
python tools/register_actions.py --pet-dir ./pet # 改仓库里的这份
python tools/register_actions.py --dry-run       # 只预览
```

### 命名规范

| 前缀 | 落到配置的哪里 | 播放时机 |
|---|---|---|
| `待机-xxx` | `animations.idle` | 待机循环，多个轮换 |
| `回应-xxx` | `animations.clicks` | 点击宠物 |
| `转向-xxx` | `animations.turn` | 转向 |
| `拖拽-xxx` | `animations.drag` | 被拖拽 |
| `移动-xxx` | `animations.moves.actions` | 随机走动 |
| `小动作-xxx` / `仪态-xxx` / `俏皮-xxx` | `animations.categories`（银月专属） | 待机中随机插入 |
| `碎碎念-xxx` | `animations.events.whisper` | 说碎碎念时 |
| `工作-<0-5>-xxx` | `animations.events.workStatus[档位]` | 对应工作状态 |
| `余额-<0-5>-xxx` | `animations.events.balance[档位]` | 对应余额档位 |

`workStatus` 档位：`0` 思考 / `1` 工作 / `2` 整理 / `3` 等待 / `4` 成功 / `5` 出错。
`balance` 档位按余额已用百分比：`0` <20% / `1` <40% / `2` <60% / `3` <80% / `4` <100% / `5` =100%。

不带前缀或前缀认不出的文件会被跳过，并提示改名。

### 空槽会让整段动画失效

`events` 池里的槽位**不能是空字符串**。`lib/index.js` 的 `animationsValid()`
见到 `""` 就判整段 `animations` 非法，插件回落到内置默认动画，且不报错。

注册器补空档位、替换失效引用时都会填一个真实存在的兜底动画名（默认 `待机`），
并在写盘前自检；手动改配置时也请遵守这条。

### 素材规范

- 容器：WebM，视频编码 VP9，带 alpha 通道（`-pix_fmt yuva420p -auto-alt-ref 0`）
- 画布：**1280×720**（dsh-pet 基准 640×360 的 2 倍），24fps
- **脚底基线 y=655、人物高约 528、水平中心 x≈625** —— 与包里现有五套一致，
  否则切换时会「跳一下」
- 人物在画面里的占比：脚底约在画面 91% 高度处（对应 dsh-pet 的 `FEET_Y`），
  对不上会出现悬空或踩空

> 这几个数字不用手算：`tools/build_asset.py` 会解码 `待机.webm` 量出当前基准，
> 再把新素材缩放到同一位置。换了基准素材它也会自动跟着变。

> **动作本身会改变身高时**（行礼、鞠躬、坐下、伸懒腰），源素材的全片身高中位数
> 会偏小，按中位缩放会把人放大。这种情况用 `--fit-h` 显式告诉工具「站姿身高」是多少：
>
> ```bash
> python tools/build_asset.py 行礼.mp4 --name 仪态-贵妇行礼 --fit-h 662
> ```
>
> 先用 `--dry-run` 看逐帧身高，取站姿那一段的中位数。实测：全片中位 636、
> 站姿 662，若按中位缩放，站姿会变成 549 px（基准 528，大 4%）；指定 `--fit-h 662`
> 后站姿正好落在 526。

> macOS Safari 需要 `.mov`（HEVC with Alpha）。dsh-pet 会自动优先找
> `pet/yinyue-animation/mov/` 下的同名文件，找不到再退回 `.webm`。

### 不知道做什么动作？

按银月的人设（安静、温和、有点小骄傲）想了几个方向，供参考：

- **待机类**：呼吸起伏、尾巴轻摆、抬眼、垂眸、理头发
- **小动作类**：托腮、掩口轻笑、拂袖、抱臂、伸懒腰、看别处
- **回应类**：挥手、点头、掩口轻笑、微微躬身
- **状态类**：翻书、写画、沉思、左右张望（对应工作档位）

用视频生成工具做的时候，提示词里把「角色长什么样」「画面怎么构图」「做什么动作」
「多长」分开写，比一句长句效果好得多。
